# 함정 체크리스트

## 0. 완성 조건 다섯 가지 (대회 참가 페이지 STEP 04)
- [ ] 실제로 돌아가는 시스템: 입력을 넣으면 확인, 판단, 승인, 상태 변경까지 이어진다. 외부 승인·발주는 모의 회신으로 대신해도 된다.
- [ ] 세 가지 상황 시연: 정상, 조건 변경, 정보 부족 또는 승인 거절. 2번과 3번은 이어서 보여도 된다.
- [ ] 나만의 확장 1개 이상: 데이터·조건·예외를 하나 더 다루고, 그게 실제 판단이나 처리를 바꿔야 한다.
- [ ] 다른 부서 영향 1개 이상: 내 결정이 다른 부서 목표·제약에 영향을 주고, 그 때문에 대안이나 계획이 달라져야 한다. 확장과 같은 사례로 보여도 된다.
- [ ] 원본과 가정 구분: 제공 데이터로 확인한 것과 내가 가정하거나 새로 만든 데이터를 구분해 표시한다. 원본 파일은 고치지 않는다.
- 미완성: 대시보드, 차트, "권고합니다" 보고서, 기획서만 있는 경우.
- 완성: 판단 뒤에 승인 요청, 작업 생성, 상태 변경이 실제로 일어나고, 바뀐 상태가 다음 판단에 쓰인다.

출처: `00_common/data_dictionary.md`, `00_common/calculation_definitions.md`
계산 결과를 내기 전에 해당 항목을 하나씩 확인한다.

## 공통
- [ ] 기준일은 2026-07-01이다. 이사회는 기준일 + 5일, 의사결정 범위는 2026-07~09 90일이다.
- [ ] CSV는 파이프(`|`) 구분, UTF-8로 읽는다. `NONE`은 결측이 아니라 "해당 없음" 코드다.
- [ ] 금액은 원 단위 정수, VAT 제외다. 천원 단위로 착각하지 않는다.
- [ ] 매출은 출하일(`ship_date`) 기준이다. 수주일(`order_date`)로 집계하지 않는다.
- [ ] 외화 원료 환율은 발주일 기준이다. 입고일 환율을 쓰지 않는다.
- [ ] 주차는 월요일 시작, 영업일은 월~금, 공휴일 없음.

## 데이터 규모
- [ ] 재고·자금·손익 계열은 실제 규모다. 30억 약정 하한과 직접 비교해도 된다.
- [ ] 마케팅 주문·반품·쿠폰·광고·유입·예산 계열은 표본이다. 비율·순위·추세만 쓴다.
- [ ] 두 계열을 절대금액으로 합산하거나 대사하지 않는다.
- [ ] 표본 수치를 전사 금액으로 키워 주장하지 않는다.
- [ ] 금액을 못 잰다는 이유로 판단을 미루지 않는다. 배분 방향과 보고 지표 신뢰성으로 크기를 말한다.

## 1. Corevia 마진 분해
- [ ] 구매단가가 아니라 `applied_unit_cost_krw`(실제 투입 단가)로 분석한다.
- [ ] 기준월은 2024-07, 기준 환율은 1,320이다.
- [ ] 단가×환율 교차항은 환율 효과에 넣는다.
- [ ] 1,320을 그대로 쓰면 1% 미만 잔차가 남는다. 실효환율 역산도 인정된다.
- [ ] 제품군(PL-0n) × 원료(M-x)별로 쪼갠다. 전사 합산으로 원인을 가리지 않는다.
- [ ] 원료 통화(`m_material_cv.currency`)를 확인한다. KRW 원료는 환율과 무관하다.
- [ ] 고객별 `cost_linked_clause`로 판가 전가 가능/불가를 나눈다. "판가 올리면 된다"는 오답이다.
- [ ] `revenue_share_pct`는 고정값이고 12개사 합계 95.5%다. 미귀속 4.5%를 고객에 배분하지 않는다.

## 2. Masil 현금 시뮬레이션
- [ ] 약정 위반은 영업일 하루라도 종가 < 30억이면 성립한다. 기간 평균이 아니다.
- [ ] 가용현금은 `closing_balance`만이다. 크레딧라인·MMF는 넣지 않는다.
- [ ] 실적 구간은 자금일보 종가를 쓰고, 기초+입금−출금=기말 항등식으로 검증한다.
- [ ] 전망 구간은 직접 일별/주별로 재시뮬레이션한다.
- [ ] 기초 = 기준일 자금일보 종가.
- [ ] 회수 = AR aging `outstanding_krw`를 `due_date`에 배치.
- [ ] 지급 = AP aging 중 `po_id = 'NONE'` 행만 `payment_due_date`에 배치.
- [ ] 기타 유출 = 발주서 `amount_krw`를 `payment_due_date`에 배치.
- [ ] 발주번호가 있는 AP 행을 넣으면 이중계상이다.
- [ ] 재무팀 공식 전망(`fin_cash_forecast_ms`)은 정답이 아니다. 내 결과와 대조하고 차이 원인을 설명한다.
- [ ] LC-0001 결제조건 변경 공지와 약정 조건 문서를 함께 반영한다. 회수 시점이 바뀌면 하회 시점도 바뀐다.

## 3. 재고 커버·발주
- [ ] 커버(주) = on_hand ÷ 최근 4주 평균 주간판매량.
- [ ] 운송 중 재고는 커버 계산에 넣지 않는다. 발주량 계산에서만 뺀다.
- [ ] 예약수량이 없으므로 가용수량 = on_hand.
- [ ] 최종 발주량은 MOQ 제약을 반영한다.

## 4. 캠페인 실질 ROAS
- [ ] 명목 ROAS와 실질 ROAS(공헌이익 기준)를 구분한다.
- [ ] 마케팅비 = 광고비 전액(인플루언서 + 퍼포먼스 + 오프라인).
- [ ] 원가·채널수수료·물류비는 `mkt_cost_master_ms` 고정값을 쓴다.
- [ ] 귀속은 last-click 7일.
- [ ] GMV는 쿠폰 반영 후, VAT 제외다. Net Revenue = GMV − 반품환불.
- [ ] 쿠폰 행은 주문당 1건이다. 중복 적용은 `stacked_flag`로 본다.

## 5. Celtonic 정상화 EBITDA
- [ ] 조정 항목은 전액 인정도 전액 부인도 아니다. 항목별로 판단한다.
- [ ] 3년 연속 반복되는 "일회성" 항목은 경상비일 수 있다.
- [ ] 분기 손익의 4개 조정 컬럼은 이름일 뿐 일회성이라는 뜻이 아니다.
- [ ] 고객 비중은 계약 만료일과 함께 봐야 이탈 손실 규모가 나온다.

## 6. 품질 회수 판정
- [ ] 회수 대상 = 불량 확정(True) AND 배치 불량률 ≥ 10%.
- [ ] 보류·False 건은 회수가 아니라 조사·소명 대상이다.
- [ ] 판단 단위는 배치다. 원료 로트(`input_lot_ids`)로 추적을 시작한다.

## 7. 기타 지표
- [ ] 재구매율 = 90일 내 재구매 고객 ÷ 최초구매 고유 고객. 기준 22%.
- [ ] 반품률은 금액 기준, 환불완료일 기준 집계. 기준 8%.
- [ ] DSO = 기말 미수금 ÷ 기간 매출 × 기간일수. 기준 55일.
- [ ] CTR이 높아도 CVR이 낮으면 CAC가 높다. 명목 지표와 실질 효율을 나눠 본다.
- [ ] 가동률은 라인 단위다. 공장 단위는 `capacity_qty` 가중평균이다.
- [ ] CAPEX는 금액이 아니라 `added_capacity_qty`로 C-201 물량 소화 여부를 판단한다.
- [ ] 채널 벤치마크는 동종업계 기준선이지 Masil 실적이 아니다.

## 8. 동일 관련자 판정
- [ ] 대표자·주소·정산계좌 중 2개 이상 일치하면 동일 관련자다.
- [ ] 일치 관계는 전이적으로 묶는다.
- [ ] 실제 입금계좌(`fin_collection_history_cv.bank_account_no`)도 대조한다.

## 9. 문제지 A05 데이터 이용 기준 (원본 문서와 충돌하면 이쪽 우선)
- [ ] 원본 폴더는 손대지 않는다. 정제·매핑·확장 데이터는 별도 폴더에 두고 원본 행까지 추적되게 한다.
- [ ] 원본 기록, 부서 주장·분석, 내 가정·합성자료, 계산 결과를 구분해 표시한다.
- [ ] 재무팀 현금 전망, `recurring_flag`, `normalized_ebitda`는 부서 산출물이다. 읽기만 해서는 검증이 아니다.
- [ ] 사건의 발생일과 적용일을 따로 기록한다.
- [ ] 수요 전망, 영업기회, 확정 주문, 생산계획, 생산 실적, 출하, 현금 회수의 상태를 구분한다.
- [ ] SKU, 제품군, 배치, 원료 로트, 공장, 라인은 집계 수준이 다르다. 이름이 비슷하다고 일대일 대응을 가정하지 않는다.
- [ ] 원료 투입일이 입고일보다 빠르거나 누적 투입량이 입고량을 넘는 행이 있다. 물량 완전 재현은 요구되지 않는다.
- [ ] 품질 출하(SBL 계열)와 매출 출하(SH 계열)는 직접 연결되지 않는다. 매핑하면 확인된 관계인지 합성인지 밝힌다.
- [ ] 90일 재구매는 기준일까지 관찰이 끝나지 않은 고객이 있다. 미성숙 고객을 비재구매로 단정하지 않는다.
- [ ] C-201 입찰 마감일과 납품 개시일은 다른 정보다. 개시일은 확인 요청이나 가정으로 보완한다.
- [ ] 설비 전환·증설의 택일 또는 병행은 수락 물량·기간·부분납품 조건에 따라 달라진다. 전제를 밝힌다.
- [ ] 주문 행에 수량이 없다. 원가·배송비를 주문당 적용하는지, 환불 시 원가·수수료 회수 여부, 반품 물류비 횟수를 가정으로 명시한다.
- [ ] 동일 주문에 쿠폰과 환불을 다시 차감하지 않는다. 인플루언서비가 광고비에 이미 들어 있으면 다시 더하지 않는다.
- [ ] ROAS 분모가 0이면 계산 불가로 처리한다. 비용 범위와 기간을 함께 적는다.
- [ ] 과거 평균 효율에 예산을 곱한 예측은 선형성·포화·표본 한계를 밝힌다.
- [ ] 약정 하회 예상 구간의 신규 현금 약정은 기존 상위 승인 규정을 적용한다.
- [ ] 품질 회수는 품질위원회 의결로 실행한다. 원인 조사와 회수 실행의 승인 절차는 다르다.
- [ ] 관련 거래처는 관계 정황과 부정 확정을 구분한다.
- [ ] 독점 공급·생산능력·계약·승인 제약을 없애는 가정은 기본 사실이 아니라 대안 시나리오로 분리한다.
- [ ] 모의 회신·검사 결과는 가상 입력으로 표시한다. 유리한 회신만 만든 성공 시연은 검증이 아니다.
- [ ] 실제 작동, 모의 처리, 설계 단계를 구분한다.
- [ ] 이전 대회의 3시간 제한·프롬프트 로그 제출·배점 안내는 적용하지 않는다.

## 10. 승인 권한 경계 (`approval_authority_policy.md`)
- [ ] AI는 권한 경계를 넘는 결정을 자동 확정하지 않는다. 사람에게 상신한다.
- [ ] 재고 발주 승인은 SCM, 품질 회수는 품질위원회, C-101 재협상·판가는 영업 임원이다.
- [ ] 입찰 참여·투자 승인과 300억 배분은 CEO/이사회다.
- [ ] 캠페인 확대안은 건별 1천만원 이하면 마케팅팀 전결이다. 초과하거나 기안 총액이 1억원을 넘으면 Masil 대표 승인과 그룹 보고가 필요하다.
- [ ] 캠페인 확대안은 예상 GMV가 아니라 실질 공헌이익으로 판단한다. 기존 실질 성과를 함께 조회한다.
- [ ] 캠페인 계약 확정기한이 지나면 자동 확정되어 철회할 수 없다. 미결정은 묵시적 승인과 같다.
- [ ] 인플루언서 연간 전속계약은 연 10억원 초과면 CEO/이사회, 이하면 Masil 대표다.
- [ ] 미통보 자동 갱신도 체결로 본다. 되돌리려면 위약금이 발생한다.
- [ ] 캠페인 확대안 부결과 전속계약 갱신은 별개 결정이다. 두 기한을 함께 확인한다.
- [ ] INF-001 전속계약은 고정 피 연 28억원이고, 2026-07-17까지 통보하지 않으면 1년 자동 갱신된다.
- [ ] 약정 하회 예상 구간에 현금이 나가는 신규 약정은 금액·종류 불문 CEO/이사회 승인이다. 평시 전결 권한보다 우선한다.
- [ ] 판단 순서는 하회 구간 특정, 약정 유출일 대조, 구간에 들어가면 그룹 상신이다. 소액이라도 생략하지 않는다.
- [ ] 판매장려금은 거래처별 월 2백만원 이하 영업지원팀 전결, 초과는 영업임원 승인이다.
- [ ] 판매장려금 한도는 동일 관련자 그룹 단위로 합산해 적용한다.
- [ ] 대체 원료 사용 승인권자는 원본에 없다. 품질 회수 권한이나 CEO 투자 권한을 임의로 가져다 쓰지 않는다.
- [ ] 원본의 회수계좌를 지급계좌로 단정하지 않는다.
- [ ] Celtonic 원료를 Corevia의 승인된 대체재로 볼 증거는 없다.
