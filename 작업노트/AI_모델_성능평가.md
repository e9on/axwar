# AI 모델 성능평가 보고서

- 기준: 2026-11-10 · 실행 결과 파일은 `eval/results/`에 모두 보관
- 형식: 목표 · 방법 · 방향 · 결과 → 모델별 제외 이유 → 배정 제안

---

## 1. 목표
AI가 맡는 두 가지 판정을 **정확도가 충분한 모델 중 가장 싼 것**으로 고른다.
- **리뷰 해석**: 고객 리뷰가 색상 불일치인지, 변심인지, 배송 문제인지, 감정은 어떤지
- **회신 해석**: 부서 회신이 수용·조건부·거절·정보부족 중 무엇인지, 수량·날짜, **사람 확인이 필요한지**

## 2. 방법
- 문제 60개(리뷰 30, 회신 30)를 각 모델에 3번씩 풀게 하고 정답과 비교.
- 1차 실행(8개 모델) 후 **독립 검수 에이전트**가 결과를 다시 집계해 정답 오류·채점 오류·실행기 문제를 찾음 → 고친 뒤 다시 채점, Claude만 회신을 다시 실행.
- 모든 자동 테스트는 가짜 AI로, 실제 API는 이 평가에서만 사용.

## 3. 방향 — 무엇을 중요하게 봤나
1. **위험한 오답 0건**: 사람 확인이 필요한 회신을 "필요 없음"으로 판단하면 결재가 빠진 채 진행된다. 가장 무겁게 본다.
2. **같은 문제에 같은 답**(3회 일치): 시연·운영에서 결과가 흔들리면 안 된다.
3. **정확도**, 4. **비용**, 5. 응답 속도.
- 확신도는 쓰지 않는다: 틀린 답의 확신도가 맞은 답과 같았다(오답 약 250건 중 0.7 미만 2건).
- 리뷰의 "감정" 판정은 사람도 갈리는 문제가 섞여 있어(예: "제가 잘못 골랐어요" → 중립? 부정?) 모델 비교에서는 감정을 뺀 정확도를 주로 본다.

### 4-5. 앱 지시문으로 다시 평가 (2026-11-11)
앱에 넣으면서 회신 지시문이 세 군데 바뀌었다. 바뀐 지시문으로 Haiku에 회신 30문제를 3번씩 다시 풀게 했다.
- 바뀐 곳: ① "연도는 2026년이다" → "기준일은 (날짜)다"(날짜를 코드에 박지 않기 위해) ② 출력 예의 날짜 → "YYYY-MM-DD" ③ "위험 경고만 붙은 '전량 가능'은 조건부수용 + 사람 확인" 한 줄 추가(7. 한계에서 적은 보완)

| 지시문 | 전부 정답 | 위험 오답 | 안전 오답 | 3회 일치 | 비용 |
|---|---|---|---|---|---|
| 평가 때 지시문 (4-1) | 87% | 0 | 7 | 77% | — |
| **앱 지시문 (①②③)** | **82%** | **0** | 9 | **87%** | $0.014 |
| 대조: ①②만 (③ 뺌) | 80% | 0 | 9 | 90% | $0.015 |

- 정답이 줄어든 문제는 두 종류다. ⑴ 사람 확인이 필요 없는 회신을 사람에게 넘김(P07 "피크 때 1.5배까진 버텨요", P25 "2천5백 건 정도요") — 안전한 쪽 오답. ⑵ "거절"과 "정보부족" 사이를 오감(P09, P12) — 둘 다 무조건 사람 확인이라 운영 결과는 같다.
- ③을 뺀 대조 실행도 80%였으므로 ③이 원인은 아니다. 위험 오답 0을 유지하고 일치율이 올라 **앱 지시문(①②③)을 그대로 쓴다.**
- 결과 파일: `eval/results/2026-11-11T05-25-01Z.jsonl`(앱 지시문), `2026-11-11T05-26-30Z.jsonl`(대조).
- 비용: 이번 재평가 약 $0.03 → Anthropic 누적 약 $3.23.

## 5. 모델별 제외 이유
| 모델 | 제외 이유 | 다시 볼 조건 |
|---|---|---|
| **Gemini 3.8 Flash** | 111번 호출이 모두 실패. 실행기가 오류 내용을 기록하지 않아 원인(무료 한도, 무료 미제공, 서버 과부하)을 **확인하지 못함** → 측정 불가 | 오류 기록을 넣었으니 하루 뒤 1건 시험. "한도 0"이면 영구 제외. 단가가 Haiku보다 비싸 우선순위 낮음 |
| **Solar Mini** | 사람 확인이 필요한 회신을 "필요 없음"으로 판단한 **위험 오답 6건**(다른 모델 0건), 같은 문제 3회 일치 50%, 리뷰 정확도 82% | 없음 |
| **Solar Pro** | **위험 오답 8건**, 3회 일치 63%, 리뷰 81% | 없음 |
| **Claude Opus** | 정확도는 가장 높지만 Haiku의 약 40배 비용. 1차 실행에서 어려운 회신 문제에 빈 답이 몰려 회신 기준선으로도 쓸 수 없음 | 배정 후보·재실행에서 제외 |
| **Claude Sonnet** | 회신 정확도가 Haiku와 같은데 **위험 오답 1건**, 비용 약 16배 | 글쓰기 역할(결재권자 요약·통보 초안)은 별도 평가가 필요하면 후보 |
| Gemini 3.1 / 3.5 Flash-Lite | 제외는 아님. 회신 정확도가 Haiku보다 8~9%p 낮고, 불필요한 사람 확인이 많음(11~13건). 무료지만 사용 한도·응답 지연(약 4초) 위험 | **예비 모델**로 둠 |

## 6. 배정 제안
| 역할 | 주 모델 | 예비 | 이유 |
|---|---|---|---|
| 리뷰 해석 | **Claude Haiku** | Gemini 3.1 Flash-Lite | 감정을 뺀 정확도 100%로 동률. 시연 중 무료 한도에 걸리면 안 되므로 안정성 우선, 비용 차이는 시연 전체에 1센트 미만 |
| 회신 해석 | **Claude Haiku** | Gemini 3.1 Flash-Lite | 정확도 1위(87%), 위험 오답 0, 저렴 |
| 글쓰기(요약·반대 근거·통보 초안) | Claude Haiku | Claude Sonnet | 정답 채점이 어려워 이번 평가 범위 밖. 화면에서 품질을 보고 필요하면 Sonnet |
- Claude 호출 설정: 생각 강도 낮음, 출력 한도 2,048, 출력이 잘리면 사람에게.
- 사람에게 넘기는 기준: 확신도가 아니라 **모델의 "사람 확인 필요" 판단 + 규칙 검사**(허용 값, 거절·정보부족이면 무조건 사람 확인, 잘림).

## 7. 한계
- 문제와 정답을 Claude(작성자)가 만들어 Claude에 유리할 수 있음. 검수에서 정답 4개를 고쳤지만 완전히 없앨 수는 없음.
- 문제 30개씩이라 1~2문제 차이가 3~7%p로 크게 보임.
- Haiku의 3회 일치 77%는 Gemini 3.5(87%)보다 낮다. 앱은 같은 회신을 한 번만 해석하므로 운영 영향은 작지만, 애매한 회신은 사람 확인으로 넘기는 규칙이 이를 보완한다.
- 판정 지시문의 애매한 문구(예: 위험 경고만 붙은 "전량 가능")는 이번에 고치지 않았다. 앱의 지시문을 만들 때 보완한다.
