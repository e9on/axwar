- 작성일: 2026-11-10
- 기준일(데이터 as-of): 2026-07-01
- 상태: 사용자 검토 대기
- 근거 표기: **[원본]** 원본 데이터·문서에 있는 사실 / **[계산]** 원본으로 계산 정의대로 산출 / **[가정]** 과제용으로 정한 교육용 가정 / **[회신]** 시연 중 부서가 입력한 값

## 1. 목표

Masil의 인플루언서 전속계약 갱신과 캠페인 확대 기안을 **승인 권한 경계 안에서** 처리하는 운영 시스템을 만든다.
대시보드나 보고서가 아니라, 판단 → 승인 요청 → 작업 생성 → 상태 변경이 실제로 일어나고 **바뀐 상태가 다음 판단에 쓰이는** 시스템이다.

### 1.1 다섯 가지 완성 조건과 대응

| 완성 조건 | 이 시스템에서 |
|---|---|
| 실제로 돌아가는 시스템 | 승인, 작업 생성, 상태 변경이 DB에 저장되고 다음 판단에 반영된다 |
| 세 가지 상황 시연 | 8장의 장면 1(정상), 장면 2(조건 변경), 장면 3(정보 부족·승인 없음) |
| 나만의 확장 1개 이상 | ① 조건변경 통보의 **순액 기준 성과 피** 제안 ② **조건부 분할 승인** ③ 승인권자 변경 시 **이유 명시와 권한 이동 알림** |
| 다른 부서 영향 1개 이상 | 물류(출고 한도·분할 출고), CS(반품 대비·사유 자료), SCM(입고 일정이 2차 시점을 정함), 에이전시(콘텐츠 수정) |
| 원본과 가정 구분 | 화면의 모든 근거에 [원본]/[계산]/[가정]/[회신]/[의견] 배지, 가정 목록 화면 |

## 2. 원본에서 확인한 사실 (설계의 전제)

### 2.1 혜인(INF-001) 전속계약 [원본] `inf001_exclusive_contract_notice.md`
- 고정 피 **연 28억원** + GMV 연동 성과 피. 현 계약 만료 2026-08-31.
- 해지·조건변경 통보 기한 **2026-07-17**. 미통보 시 동일 조건 1년 자동 갱신, 갱신 후 중도 해지 시 잔여 고정 피 50% 위약금.
- 재무팀 메모: 갱신 여부는 혜인의 **기존 실질 공헌이익**을 확인한 뒤 결정해야 하는데 그 수치가 산출된 적이 없다. 기안은 이 계약의 하위 집행분이므로 함께 처리해야 한다.

### 2.2 승인 권한 [원본] `approval_authority_policy.md`
- 캠페인 확대안: 건별 1천만원 이하 마케팅 전결, **초과 또는 기안 총액 1억원 초과 시 Masil 대표 승인 + 그룹 보고**.
- 전속계약 체결·갱신: 연 10억원 초과 **CEO/이사회**. 미통보 자동 갱신도 체결로 본다.
- covenant 하회 예상 구간에 현금이 나가는 신규 약정: 금액·종류 불문 **그룹 CEO 승인**, 평시 전결보다 **우선**.
- Agent는 경계를 넘는 결정을 자동 확정하지 않고 사람에게 상신한다.

### 2.3 캠페인 확대 기안 [원본] `mkt_budget_plan_ms.csv`

## 3. 판단 원칙

1. **승인권자의 승인이 핵심이다.** 규칙이 승인권자를 정하고, 시스템은 권한을 넘는 결정을 확정하지 않는다.
2. **승인이 없으면 기본값은 거부다.** 이익보다 손실을 먼저 경계한다. 원본 규칙상 무응답은 자동 갱신·자동 확정이므로 시스템이 **기한 전에** 먼저 움직인다.
3. **기본 거부는 해지가 아니라 조건변경 통보다.** 승인권자가 사정이 있어 못 봤을 수 있고, 해지하면 이후 협상이 어려워진다. 조건변경 통보가 자동 갱신을 막는다는 해석과 통보 발송 주체(계약 담당)는 **[가정]**이다.
4. **결정이 핵심 지표와 반대면 다른 결정권자 승인을 붙인다(양방향).** 늘리는 결정인데 지표가 나쁘거나, 줄이는 결정인데 지표가 좋을 때. 판정은 규칙, 반대 근거 정리는 AI.
5. **지표가 좋은 건이 승인 없이 기한을 맞아도 기본 거부를 유지**하되, 기한 전에 더 일찍 한 단계 위로 경고한다.
6. **조건이 바뀌어 승인권자가 바뀌면 이유를 명시한다.** 규정, 바뀐 데이터, 바뀐 시점, 근거(원본·계산)를 규칙이 적고, 원래 보던 결정권자에게 알린다.

## 4. 규칙이 하는 일 (결정적, AI 없음)

### 4.1 승인권자 판정
입력: 건 종류, 금액, 기안 총액, 집행일, 하회 구간.
1. 집행일(현금 유출일)이 하회 구간 안 → **CEO/이사회** (covenant 우선 규정).
2. 전속계약 연 10억 초과 → **CEO/이사회**.
3. 캠페인 확대: 건별 1천만 초과 또는 기안 총액 1억 초과 → **Masil 대표 + 그룹 보고**. 아니면 마케팅 전결.
4. 핵심 지표와 반대 → 추가 승인(혜인 갱신: CEO에 이사회 의결 추가 / 기안: Masil 대표에 그룹 확인 추가 / 이미 CEO 사안이면 이사회 의결 추가).
- 판정마다 **적용한 규정과 근거 데이터**를 함께 저장한다.

### 4.2 승인권자 변경
- 하회 구간 재계산, 집행일 변경(분할), 금액 변경이 일어나면 4.1을 다시 돌린다.
- 결과가 바뀌면 `approver_change` 기록: 이전·새 승인권자, 규정, 바뀐 데이터, 시점, 근거.
- 이전 승인권자 할 일에 **권한 이동** 알림. 이전 승인권자는 의견을 남길 수 있고, 새 승인권자 근거 칸에 [의견] 배지로 보인다.

### 4.3 기한 관리
- 건마다 확정 기한을 둔다(전속계약 7/17, 기안은 `contract_deadline`).
- 기한 D-5 [가정]: 승인 대기면 한 단계 위로 조기 경고.
- 기한 당일까지 승인 없음 → **기본 거부** 실행: 전속계약은 조건변경 통보 초안 생성 후 계약 담당에게 발송 작업, 기안은 확정 보류(철회) 처리.

### 4.4 핵심 지표
- 실질 성과 순위: 계산 정의 1.4 실질 ROAS(Contribution Profit / Marketing Spend) 기준 인플루언서·캠페인 순위 [계산].
- 단순변심 반품률(금액 기준, 1.7) [계산].
- 배분 역전: 기안 요청 비중이 실질 성과 순위와 반대인지 [계산].
- 모두 표본 계열이므로 **비중·순위·방향**만 쓴다.
- 확인값 [계산]: 혜인(INF-001) 실질 ROAS **−0.198, 10명 중 9위**, 광고비 비중 **40.6%로 1위** → 배분 역전. 1위는 INF-002(3.703). 혜인 단순변심 반품률 3.58% vs 그 외 1.75%. CMP-0003 실질 ROAS −0.248.
- 수량 가정 민감도 [계산]: 주문 행에 수량이 없고 금액으로도 역산되지 않는다(주기성 검사에서 정수배 묶음 없음). 수량 가정을 바꿔도 혜인은 최하위권이고 음수다 — 1건=1개 −0.198(9위) / 금액 비례 −0.267(10위) / 금액 비례×2 −0.503(10위). "1건=1개"는 혜인에게 가장 유리한 가정이다.

| 회차별 추세 | 반복할수록 나빠지는지 | 최근 회차 실질 ROAS ≤ 첫 회차면 🟡 | −0.227 → −0.095 → −0.248 🟡 |
| 고객 잠식 | 다른 캠페인 고객을 빼앗았는지 | — | ⚪ 측정 불가: 표본에서 고객이 인플루언서별로 완전히 나뉨(0%) |
**측정 한계와 본전 조건** — 성과는 원본 기준 "마지막 클릭 후 7일"로 캠페인에 귀속된다(계산 정의 1.4).
- 포함: 링크를 누르고 7일 안에 산 주문(혜인 라이브는 방송 당일 10.9%, 다음 7일 24.7%, 8~30일 8.1% — 늦게 산 주문이 더 많고 물량 공식에도 반영).
- 빠짐: 클릭 없이 나중에 검색·다시보기로 산 주문, 클릭 후 8일 이상, 마지막에 다른 광고를 누른 주문 → 실력보다 낮게 잡힐 수 있음.
- 부풀림: 광고 없이도 샀을 주문까지 광고 몫으로 잡힘(Blake·Nosko·Tadelis 2015, Gordon 외 2019) → 실력보다 높게 잡힐 수 있음.
- 정확한 측정은 실험(일부 지역·고객만 노출)이 필요한데 원본에 없다. 대신 **본전 조건**을 지표로 보여준다: 본전이 되려면 기록 밖 판매가 기록된 매출의 몇 % 더 있어야 하는가 = (−최종 공헌) ÷ (마케팅 전 공헌 ÷ 매출) ÷ 매출. 혜인 약 24.7%. 결재권자가 "그 정도 숨은 판매가 있을까"를 직접 판단한다.
- 1차 공지 때 마케팅팀에 **측정 요청 작업**을 만든다: 라이브 전용 할인 코드(클릭 없는 구매 포착), 방송 전후 2주 브랜드 검색량 비교. 시스템 밖 측정이므로 결과는 회신으로 받는다.
- 겉 지표와 실질의 차이: 혜인의 클릭 후 구매 전환율은 0.92%로 1위, 고객 획득 광고비는 중간(11,679원). **데려오는 능력은 좋지만 데려온 고객의 질(반품·재구매·할인 의존·결제 지연)이 나쁘다.** 계산 정의 1.10의 "명목 지표와 실질 효율 분리"와 같은 함정.

### 4.5 물량 계산과 물류·재고 배분 (25건 공통 규칙)

**물량 공식** — 사람이 기안마다 수량을 넣지 않는다.
- 과거 실판매량 [계산] = Σ(그 주 그 상품 표본 주문 중 이 캠페인 몫 × 실제 주간 판매량). 표본은 비율로만 쓰고, 실제 규모는 재고 계열(풀스케일)에서 가져온다.
- 확대 배율 [계산] = 기안 예상 GMV ÷ 이 캠페인 과거 GMV(같은 표본 계열 안의 비율). 25건이 1.1·1.25·1.35배.
- 기안 물량 = 과거 실판매량 × 확대 배율. 날짜별 물량은 과거 일별 판매 모양을 따르되, **모든 물량은 집행일 이후에만 잡는다**(확대 예산은 집행해야 쓰기 시작한다) [가정 — 기안에 판매 일정이 없음]:
  - 라이브: 방송일 = 집행일. 과거 최대일을 집행일(첫날)에 두고, 나머지 날은 원래 순서대로 뒤에 붙인다.
  - 그 외 채널: 과거 캠페인 첫날 = 집행일.
  - 최대일이 동률이면 가장 이른 날.
- 혜인 라이브(PLAN-001) 7/27 약 16,000개(캠페인 물량의 10.9%가 하루), 다른 채널은 하루 최대 1.8~3.3%. 7/27 25건 합계 18,064개, 7/28 2,013개.
- 캠페인이 자기 상품의 표본 주문을 거의 다 차지하면(표본 몫 0.9 이상) 일반 판매까지 캠페인 몫으로 잡혀 물량이 부풀려진다 → **추정 신뢰도 낮음** 표시(PLAN-011).
- 기안 예상 GMV는 광고비의 9~11배로 적혀 있지만 실제 실적은 1.3~6.7배다. 예상 GMV는 물류 부하처럼 넉넉히 잡아야 하는 곳에만 쓰고, 성과 판단에는 실질 성과만 쓴다.

**물류 처리 능력**
- 물류팀에 날짜별로 두 값을 묻는다: ① 평소 안정적으로 처리하는 양 ② 최대 처리량(야근 포함).
- 배분 기준은 ①. ①만으로 여유가 들어 있으므로 따로 빼지 않는다.
- ①이 없고 ②만 있으면 ② × 0.85를 쓴다 [가정 — Kingman 대기열 곡선(대기 ∝ u/(1−u))이 급하게 꺾이는 지점과 창고 가동률 85% 관행. 데이터로는 표본이 작아 잴 수 없음].

**재고 장부 (상품별, 날마다)**
- 쓸 수 있는 재고 = 전날 재고 + 그날 입고 − 평소 판매(최근 4주 평균 ÷ 7) − 안전재고 최소 주수분.
- 장부상 재고가 안전재고 최대 주수를 넘으면 **재고 과잉** → SCM에 발주 조정 요청. 계속 모자라면 **재고 부족** → 그 상품 기안의 남은 물량은 입고 이후로.
- 확인값 [계산, 캠페인 없이 평소 판매만]: 기초 세 상품은 7/27에 이미 안전재고 아래(토너 8,012 vs 17,794, 에센스 4,231 vs 15,712, 수분크림 7,942 vs 15,362)이고 입고(8/18~19) 전에 바닥난다(−5,970 / −8,675 / −4,677). 리드타임 8주 > 재고 5~6주. 아이팔레트도 8/6 입고 전 −1,209. 반대로 립·쿠션은 과잉(입고 후 24~27주분).
- 한계: 평소 판매 = 최근 4주 평균(계산 정의 1.3)인데 6월에는 6/30에 끝난 캠페인 판매가 섞여 있어 7월 평소 판매를 과대평가할 수 있다. 원본에 캠페인을 뺀 평소 판매가 없어 정의대로 쓰고 화면에 한계를 표시한다. 실제 여유가 생기면 장부가 자동으로 반영한다.

**재고 부족 시 SCM 요청** — 재고 결정은 SCM 권한(승인 권한 표)이라 시스템은 수량을 정하지 않는다.
- 안전재고 위 여유분이 기안 1차에 모자라면 SCM에 요청을 만든다: 안전재고 사용 여부·수량, 그리고 쓰면 평소 고객 주문이 **며칠 일찍 품절되는지**(사용량 ÷ 하루 평소 판매)와 품절 손실 근거(매출 약 4%)를 함께 보낸다.
- SCM 응답 세 가지: **전량 허용** → 계산대로 진행 / **일부 허용(수량 입력)** → 1차 = 허용 수량과 물류 몫 중 작은 값 / **거절·무응답** → 1차를 입고 다음 날로 연기. 거절된 상태에서 수량만 줄여 안전재고를 쓰는 우회는 하지 않는다.
- 1차 수량이 처음 승인한 분할안과 달라지면 결재권자에게 **다시 승인**을 받는다(바뀐 이유 함께 표시). 공지는 캠페인 담당자가 하고, 시스템은 예약 가능 여부만 확인한다.

**날마다 배분 순서**
1. 원하는 양 = 그날 각 기안 예상 물량 + 전날 못 보내 넘어온 양.
2. 공지되어 예약된 수량을 먼저 뗀다.
3. 재고 배분: **안전재고 위 여유분**(SCM이 허용한 안전재고 사용분 포함)을 같은 상품을 원하는 기안끼리 원하는 양의 비율대로 나눈다.
4. 물류 배분: 전체 원하는 양이 처리 능력을 넘으면 **모든 기안이 자기 원하는 양의 같은 퍼센트**를 받는다(예시: 줄 수 있는 17,000 ÷ 원하는 26,600 = 64%). 자기 예상 물량보다 많이 받는 경우는 없다.
5. 실제 보내는 양 = 3과 4 중 작은 값. 못 보낸 양은 다음 날 1로 넘어간다.

**공지 수량 고정**
- 1차 수량을 소비자에게 공지하면 그 날짜의 재고와 물류를 먼저 예약해 잠근다. 이후 배분에서 건드리지 않는다.
- 공지 전에 예약 가능한지 확인하고, 모자라면 공지를 막는다(공지 후 미배송은 소비자 피해).
- 공지 후 재고가 남아도 공지 수량만 판다(표시·광고 신뢰, 한정 수량 효과 — Aggarwal 외 2011). 남은 재고는 다른 기안·평소 판매로, 넘친 수요는 2차 판단 근거로 기록한다.

**2차 집행일**
- 2차는 이월이 아니라 규칙상 기다려야 하는 물량이다: 2차 집행일 = max(입고일 다음 날, 하회 구간 종료 다음 날 8/23, 1차 집행일 + 반품 관찰 28일) → 장면 2는 **8/24**. 계약 만료(8/31) 이전이어야 한다.
- 2차 집행일이 하회 구간 밖이면 2차 승인권자를 다시 판정한다(4.2).
- 근거: Kingman 대기열(이용률 u/(1−u)), 라이브 반품 연구, 품절 손실, Test & Roll. 내부 데이터는 약한 지지임을 화면에 밝힌다.

### 4.6 2차 집행 중단 기준
- 2차는 1차 집행 후 **잠금** 상태로 시작하고, 반품 관찰 28일이 지나야 열 수 있다. 근거 [계산]: 반품 확정까지 중간값 18일, 90%가 28일, 최대 32일.
- **반품(근거 강함) → 자동 보류**: 1차 단순변심·색상불만 반품률(건수 기준)이 혜인 과거 기준선보다 **통계적으로 유의하게** 높으면 2차를 자동 보류한다. 기준 = 기준선 + 1.645 × √(기준선 × (1 − 기준선) ÷ 1차 주문 수)(한쪽 95%). 기준선과 1차 수량으로 매번 계산한다. 예: 1차 1,800건이면 단순변심 약 5.2%·색상불만 약 4.5%, 장면 2(SCM 일부 허용 3,000개)면 약 5.0%·4.3%. 오배송·불량은 물류·품질 원인이라 제외.
  - 고정 %가 아니라 통계 기준인 이유: 1,800건이면 반품률이 우연히 ±0.8%p쯤 흔들린다. 그 폭을 넘을 때만 "정말 늘었다"고 본다.
- **리뷰(근거 약함) → 경고와 사람 확인**: 리뷰는 원본에 없어 내부 기준선이 없고, 온라인 리뷰는 J자 분포(만족·불만 극단이 주로 작성)라 고정 비율이 품질을 잘 반영하지 못한다(Hu·Pavlou·Zhang). 그래서 리뷰만으로 자동 보류하지 않는다. AI가 색상불일치 리뷰를 찾으면 콘텐츠 수정 요청과 담당자 확인으로 넘기고, **수정 확인 전까지 2차는 잠금 유지**한다.
- 이전 안의 고정 임계값(색상불일치 15%, 부정 30%)은 근거가 없어 폐기했다.
- 반품 사유 4갈래 처리: 단순변심 → 2차 판단, 색상불만 → 콘텐츠 수정 요청, 오배송 → 물류, 불량 → 품질.
- 콘텐츠 수정 요청 시 담당자(캠페인 담당자)는 수정본과 원본 대비 비교 자료를 **필수 첨부**한다. 회신이 없으면 2차 보류 유지.
- 혜인 갱신이 확정되지 않았으면 8/31 이후로 넘어가는 집행은 막는다.

## 5. AI가 하는 일

규칙으로 표시할 수 없는 복합 판단만 맡는다. 숫자, 기한, 권한, 기본 거부는 규칙이 맡는다.

| 역할 | 입력 | 출력 | 채점 가능 |
|---|---|---|---|
| 리뷰 해석 | 리뷰 문장 | 사유 6종, 감정, 영상과 색 차이 언급, 확신도 | 예 |
| 회신 해석 | 요청과 부서 회신 | 수용/조건부수용/거절/정보부족, 처리 한도, 날짜, 사람 확인 필요, 확신도 | 예 |
| 승인권자 브리핑 | 건의 규칙 판정과 근거 | 요약 | 기준표 필요 |
| 반대 근거 정리 | 결정과 핵심 지표 | 반대 근거 목록 | 기준표 필요 |
| 조건변경 통보 초안 | 계약 조건과 재협상안 | 통보문 초안 | 기준표 필요 |

- AI 출력에는 항상 [AI] 표시와 확신도를 붙인다.
- 회신 해석에서 `needs_human=true`이거나 확신도가 기준 미만이면 사람 확인으로 넘긴다. 확신도 기준은 성능평가 결과로 정한다(틀린 답의 확신도가 실제로 낮은지 확인 후).
- AI 호출, 입력, 출력, 모델, 확신도를 모두 처리 기록에 남긴다.
- 판정 지시문은 `eval/prompts.py`와 앱이 **같은 파일**을 쓴다(구현 때 백엔드로 옮기고 시험이 그것을 가져다 쓴다).

### 5.1 모델 배정
- 후보: Claude Haiku 5.5 / Sonnet 5.5 / Opus 5.5, Gemini 3.1·3.5 Flash-Lite / 3.8 Flash, Upstage Solar Mini 4 / Pro 4. OpenAI는 당분간 제외.
- 방법: 업무별 정답 있는 문제 30개 × 3회. Opus 수준 정확도에 가까운 가장 싼 모델을 업무별로 배정.
- 결과: **성능평가 진행 중, 결과 나오면 이 절을 채운다.**
- 앱은 모델을 설정으로 바꿀 수 있는 구조로 만든다.

### 5.3 API 예산
- Anthropic 충전 $5, 성능평가로 약 $3 사용 → 남은 약 $2를 나눈다: 자동 테스트 $0(가짜 AI), 실제 연결 확인 $0.10, 시연·배포 $1.00, 추가 성능평가 $0.50(Opus 제외), 예비 $0.40.
- AI 호출마다 모델·토큰·비용을 기록하고, 앱 전체 $1.00·하루 $0.30을 넘으면 AI를 멈추고 규칙 판정만 보여준다.
- Gemini 무료 등급이 성능 기준을 넘으면 먼저 쓴다.

### 5.2 나만의 확장: 순액 기준 성과 피
- 조건변경 통보 초안의 재협상안: 돈의 절대량(고정 피)과 정산비율 두 축.

## 7. 구조

### 7.1 스택
- 백엔드: Python 3.11, FastAPI, uv.
- 프론트: TypeScript, React, Vite.

### 7.2 백엔드 모듈
| 모듈 | 책임 |
|---|---|
| `data` | 원본 CSV 읽기(파이프 구분, NONE 처리), 읽기 전용 |
| `calc` | 현금 시뮬레이션, 실질 ROAS, 반품률, 재고 커버. 계산 정의 그대로 |
