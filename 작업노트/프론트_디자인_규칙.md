# 프론트엔드 디자인 규칙

- 정한 날: 2026-11-10
- 적용 범위: 이 프로젝트의 모든 화면 작업

## 규칙

1. 디자인을 시작하기 전에 디자인 방향을 먼저 정의한다.
2. 흔한 AI 생성형 UI 패턴을 지양한다.
3. 페이지마다 일관된 디자인 시스템을 유지한다.
4. 타이포그래피, 색상, 여백을 체계적으로 정의한다.
5. 카드 중심의 획일적인 레이아웃을 피한다.
6. 실제 서비스 수준의 UI 완성도를 목표로 한다.
7. 반응형 디자인을 적용한다.
8. 모든 버튼과 인터랙션은 실제 작동해야 한다.
9. 구현 후 브라우저에서 직접 화면을 확인한다.
10. 시각적 문제를 발견하면 수정하고 다시 확인한다.

## 디자인 리뷰 항목

| 항목 | 확인 방법 |
|---|---|
| 레이아웃 균형 | 데스크톱·태블릿·휴대폰 폭 스크린샷 비교 |
| 타이포그래피 | 글자 크기 단계와 굵기가 토큰에서만 나오는지 |
| 색상 일관성 | 색이 토큰에서만 나오는지, 근거 배지 색이 화면마다 같은지 |
| 컴포넌트 간격 | 여백이 간격 단계(토큰)에서만 나오는지 |
| 시각적 위계 | 승인권자가 가장 먼저 봐야 할 것(규칙 판정, 기한, 버튼)이 가장 먼저 보이는지 |
| 반응형 동작 | 휴대폰 폭에서 가로 스크롤 없음, 결정 칸 위치 |
| 접근성 | 키보드 이동, 초점 표시, 명도 대비, 버튼 이름 |
| 인터랙션 완성도 | 모든 버튼이 실제 상태를 바꾸는지, 불러오는 중·실패·빈 상태 |

## 작업 순서

1. 디자인 방향 문서(무드, 참고, 하지 않을 것) 작성 → 사용자 확인
2. 디자인 토큰(글꼴, 크기 단계, 색, 간격, 모서리, 그림자) 정의
3. 테스트 먼저 → 화면 구현
4. Playwright로 세 가지 폭 스크린샷 확인
5. 위 8항목 리뷰 → 문제 수정 → 다시 확인
